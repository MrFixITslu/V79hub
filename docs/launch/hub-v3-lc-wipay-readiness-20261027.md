## WiPay LC v1.0.1 contract, from 27 Oct support email and attached 2021 PDF

Business sign-up `https://lca.wipayfinancial.com/v1/`; sandbox `https://lca.wipayfinancial.com/v1/us_gateway`; live `https://lca.wipayfinancial.com/v1/us_gateway_live`. POST form-url-encoded is recommended; GET also documented. Required request: `developer_id` (sandbox 1) and `total` as **USD, two decimals**. Optional: `email`, `name`, unique `order_id` (format ad[1-16]), `phone`, `return_url`. The API redirects to hosted page or an error page. The hosted page later redirects the browser by GET to return_url with `order_id`, `total`, `hash` (success only), `status` (success/failed), `responseCode` (Y/N), `reasonCode`, `reasonDescription`, `transaction_id`, `D` (described as currency), and optional data/date/name/email. Transaction ID is described as random number, developer ID, order ID and YYYYMMDDhhmmss separated by dashes.

For successful returns the documented MD5 input is **order_id + total + API key, no separators**. PR #196 currently computes MD5 over **transaction_id + total + API key**, uses a Trinidad sandbox default and fields including `account_number`, `currency`, `response_url`, `method`, `data` and `country_code`. This cannot be presumed compatible with LC v1.0.1. The older pricing catalog also has a hardcoded `usdDivisor: 2.7` and `displayPrice` conversion; that value is not an owner-approved checkout exchange rule. Keep these branches separate from the Hub UI cutover.

**Payment design:** create a dedicated LC adapter with an allowlisted LC endpoint, developer ID, USD order amount represented as integer cents and a unique <=16-character order reference; persist plan/version, tenant, amount, currency, merchant/environment and payment intent before redirect. Server validates exact persisted order ID/total, MD5 in constant-time comparison, status success and responseCode Y, developer ID within the transaction identifier, single-use transaction ID and atomic ledger transition. Reject missing/conflicting parameters, another tenant, expired/cancelled orders, wrong environment, duplicate/foreign transaction and uncertain writes. Treat a matching redirect as **provisional** because its hash lacks status, responseCode, currency, merchant ID and transaction ID, and a browser is not an independent settlement channel. Hold entitlement activation until WiPay provides an authenticated server-side transaction lookup or signed notification and the ledger reconciles to it; absent that, an owner-reviewed dashboard settlement/manual grant is the only controlled option. Record refunds/chargebacks as separate idempotent events and reconcile dashboard/bank payout; never reverse an old financial ledger by image rollback.

**BLOCKED: automatic paid activation.** Ask WiPay for an authenticated transaction-status endpoint/webhook (including refund, chargeback and settlement events), proof binding status, USD amount, merchant/developer identity and transaction ID, its replay/signature contract and test credentials. Confirm whether `D` is actually the currency field, callback parameter examples and exact LC-only accepted request fields. The 2021 PDF may not reflect current platform behavior; obtain current LC documentation or written confirmation.
